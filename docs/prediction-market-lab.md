# Prediction Market Lab v0.1

## Purpose

The prediction-market lane exists to answer one question before live trading work is allowed to begin:

> Can our forecasting system produce genuinely out-of-sample probabilities that are better than the market probabilities available at the same time?

The project deliberately starts with measurement rather than execution. A profitable-looking backtest is not evidence if it uses future information, unrealistic prices, related-event leakage, stale baselines, or a weak control.

## v0.1 architecture

```text
historical resolved markets
          |
          v
fixed-lead benchmark builder
          |
          v
freshness + parent-event guards
          |
          v
frozen development + temporal holdout
          |
          v
sanitized forecaster input
          |
          v
model probability vs market probability
          |
          v
Brier / log loss / calibration / slices
          |
          v
keep, reject, or refine the forecasting hypothesis
```

No live wallet or order path belongs in this phase.

## Data contract

Each case contains the historical question, a contemporaneous market probability, final binary outcome, and strict temporal cutoffs. Forecasters do not receive the final outcome or observed resolution timestamp. Blind runs can additionally hide the market probability.

A row is rejected when the market price or research cutoff is after the forecast timestamp, when resolution is not later than the forecast, or when duplicate forecast observations are detected. The clean Polymarket benchmark additionally rejects snapshots more than 72 hours older than the exact seven-day target and purges holdout markets whose parent event appeared in development.

Model weights count as information. Historical scored forecasts must use a model with a defensible pre-forecast knowledge/training cutoff. A current model that may already know a resolved outcome is not a valid historical forecaster merely because the prompt omits the answer.

## Evaluation semantics

The market is the reference forecast we have to beat. Primary metrics are model and market Brier score, Brier delta, Brier skill versus market, binary log loss, expected calibration error, and observation-level win rate. Reports are also sliced by category, market-probability bucket, and forecast horizon.

Negative Brier delta is better. Forecasting skill alone does not prove profitability.

## Historical sources

Two reproducible acquisition paths exist:

- Becker archive adapter and DuckDB builder, pinned to `Jon-Becker/prediction-market-analysis` revision `2276382cb616107db8c8647803bffa4a0d7091f8`;
- public Polymarket Gamma + Data APIs, used for the first clean real benchmark.

The Becker archive is large and must stay outside Git. Public acquisition commands are explicit and are not run inside normal unit-test CI.

## Clean Polymarket benchmark v0.1

The first reference benchmark was generated by GitHub Actions run `34467576128`. Its exact provenance and hashes are recorded in `docs/benchmarks/polymarket-public-v0.1-clean.json`.

Selection policy:

```text
actual close field:       closedTime
forecast horizon:         7 days before actual close
maximum price staleness:  72 hours
minimum market volume:    100
raw usable questions:     340
temporal split:           newest 25% initially reserved for holdout
parent-event policy:      purge holdout siblings seen in development
```

Final clean split:

```text
development questions:    255
holdout questions:         73
development parent events: 84
holdout parent events:     19
parent-event overlap:       0
max observed staleness:    64.98 hours
```

Holdout deterministic baselines:

```text
market baseline          Brier 0.07668665   delta +0.00000000
binned calibration (10) Brier 0.07842676   delta +0.00174011
constant 50%            Brier 0.25000000   delta +0.17331335
```

The market remains the best deterministic baseline. No alpha has been demonstrated. That is a result, not a failure.

## Build / reproduce a public Polymarket benchmark

```bash
cd packages/prediction-lab
python -m pip install -e ".[dev]"

prediction-lab-fetch-polymarket \
  --max-questions 340 \
  --candidate-multiplier 4 \
  --minimum-lead 7D \
  --maximum-price-staleness 3D \
  --minimum-volume 100 \
  --holdout-fraction 0.25 \
  --max-market-pages 12 \
  --output-dir data/prediction-lab/polymarket-public-v0.1
```

The command stores the exact market/trade records used, freezes development/holdout CSVs, and writes SHA-256 manifests. Large generated data remains outside Git; provenance records belong in Git.

## Run deterministic baselines

```bash
prediction-lab-baselines \
  data/prediction-lab/polymarket-public-v0.1/development.csv \
  data/prediction-lab/polymarket-public-v0.1/development.manifest.json \
  data/prediction-lab/polymarket-public-v0.1/holdout.csv \
  data/prediction-lab/polymarket-public-v0.1/holdout.manifest.json \
  --output data/prediction-lab/polymarket-public-v0.1/baselines.json
```

The market baseline is a scientific control. Its model Brier must equal market Brier and its Brier delta must be zero. If it ever appears to beat itself, the evaluator is broken.

## Codex handoff rule

The deterministic laboratory has reached the handoff condition:

```text
real historical source
  -> fresh fixed-horizon observations
  -> event-independent frozen holdout
  -> deterministic baselines
  -> trusted evaluation report
```

Codex should now work on M4 only. It must not add live trading, wallet code, NautilusTrader, TradingAgents, or autonomous strategy mutation while the first research forecaster remains unproven.
